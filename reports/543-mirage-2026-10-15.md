## Block F — Interview Plan (5 STAR+R Stories)

### Story 1: LeaseI — 8-Agent Multi-Step Agentic Pipeline
**Theme:** Agentic systems, multi-step planning, production eval
**S:** Needed to build an AI platform for lease compliance operations that could investigate support tickets end-to-end — not just answer questions, but trace root causes across settings, historical tickets, and release history.
**T:** Design and ship a multi-agent LangGraph system that could handle the full investigation workflow with production-grade reliability.
**A:** Built an 8-agent LangGraph StateGraph with real conditional edges: triage → retrieval → Config/History/StructuredData parallel agents → reasoning → validation → HITL escalation when confidence is below threshold. Every regulated call routes to human or deterministic validator — enforced in code, not just documented. Built the RAG pipeline hand-rolled (TF-IDF + cosine reranking, section-aware chunking) so I understood every retrieval choice. Added eval harness via AgentProbe: 1,240 test cases, LLM-as-judge scoring, CI regression gating.
**R:** 93.6% precision, 87.9% F1 across eval set. System correctly traces false-ineligibility ticket to misconfigured setting tagged to specific release — the canonical hard case. Safety boundary adversarially tested for tenant surface: never auto-resolves eligibility at any confidence level.
**Reflection:** Multi-step planning requires state design first. The conditional edges in LangGraph were only reliable once I'd drawn the full state machine on paper before writing a line of code. Eval calibration is harder than application prompts — meta-evaluation (testing the judge) matters as much as the system being judged.
**Best for:** "Tell me about an agentic system you built," "How do you ensure quality in multi-agent pipelines," "Describe a complex technical system you owned end-to-end"

### Story 2: AgentProbe — Eval Framework as Production Infrastructure
**Theme:** Evaluation systems, context engineering, CI-gated quality
**S:** Production LLM outputs fail in non-obvious ways — silent errors that look correct but contain hallucinations or misattributed information. Needed an eval system that could catch these automatically without manual QA per run.
**T:** Build a systematic, provider-agnostic evaluation framework that blocks production deploys when agent quality drops.
**A:** Built 5-metric LLM-as-judge eval engine: factual accuracy, hallucination rate, retrieval quality, completeness, compliance. Integrated into GitHub Actions CI/CD so failing runs block automatically. Added LLM Router for dynamic tool selection across 5 providers — each provider routed based on task type, latency budget, and cost. Built 3 LangGraph agents (Orchestrator, RAG Tracer, Auto Fix) for multi-step evaluation with auto-remediation.
**R:** Zero manual QA per test run. CI pipeline blocks regressions before they reach production. Used to evaluate LeaseI across 1,240 test cases — caught 2 hallucination patterns that would have shipped without the eval gate.
**Reflection:** The judge prompt is the hardest part of LLM-as-judge. Calibration matters — if the judge is wrong, everything downstream is wrong. Spent more time testing the eval logic than the application logic.
**Best for:** "How do you measure agent quality," "Tell me about evaluation infrastructure you've built," "How do you ship AI reliably"

### "What's your approach to context engineering and token optimization?"
> "Context engineering is about giving the model exactly what it needs to answer correctly — no more, no less. At Intuit, I built RAG-grounded prompts where every answer is sourced from retrieved customer records; structured-output schemas that constrain model outputs downstream; and prompt management that versioned each template so regressions were trackable. Token optimization in LeaseI came from the RAG design: hand-rolled TF-IDF with cosine reranking returns the most relevant clauses, not the most text — so context windows stay efficient. In AgentProbe, the LLM Router selects providers based on task type and latency budget, which implicitly optimizes token cost."

### "How do you approach building evaluation frameworks?"
> "I treat eval as a first-class engineering problem, not a QA afterthought. In AgentProbe I built a 5-metric LLM-as-judge engine — factual accuracy, hallucination rate, retrieval quality, completeness, compliance. The key insight: the judge prompt needs to be tested and calibrated before you trust it to gate production. I spent more time testing the eval logic than the application. The eval is integrated into CI/CD: failing runs block before reaching production. On LeaseI, I ran 1,240 test cases through AgentProbe — caught 2 hallucination patterns that would have shipped without the gate. That's the ROI of an eval framework: it finds the bugs you don't know exist."
